# Persistent Dexter supervision

This extends the pinned Dexter Agent; it does not replace its loop or add a second provider. Non-blind roles receive `read_agent_thread`, `read_tool_result` and `wait`. Backtester permissions, fixed Opus 4.6, numeric-only input, separate histories and absence of live/file tools are preserved.

- `create_agent` and `message_agent` keep their waiting default. `wait_for_result=false` launches a persistent visible descendant and returns its ID for later supervision. Existing descendant ownership checks still apply.
- `read_agent_thread` is a same-fund, read-only conversation page. Default is the latest eight messages; `next_cursor` pages backward. At most 20 messages and 16,000 text characters per call, with explicit truncation. Optional activity includes visible tool results, never internal reasoning. Reads do not message the target or merge conversations.
- `wait` accepts 0.01–3600 seconds and optional descendant IDs. It resumes when any specified child finishes or the timer expires. It releases one worker slot and reacquires before model work, including parallel waits. Stop/pause interrupts it; queued reacquisition cannot prevent cancellation. A wait is not a persisted schedule.
- The root/orchestrator retains Dexter's in-flight messages, tool IDs and compaction across 24-turn windows. Each boundary is a continuation checkpoint, not completion. A root response while descendants are active becomes a monitoring checkpoint, followed by a capacity-free child/timer wait and another supervision pass. Provider errors and exhaustion stay errors. Limits are four hours or 2,400 aggregate model turns per invocation, not guaranteed work duration. Specialists retain 12 turns; blind evaluators retain three.
- The canvas and agent workspace show Waiting/Monitoring during those states. Saved progress contains the latest 12 visible tool results, not chain of thought. Restart marks interrupted work stopped; the next explicit/scheduled start gets saved conversations, progress and workspace files. In-flight process memory/timers do not survive restart. The separate opt-in fund scheduler owns hourly recovery and overlap controls.

The native result-path issue is real: upstream large-result storage uses private `DEXTER_STATE_DIR/tool-results`, while native read_file permits only shared workspace files. `read_tool_result` lists actual files and reads bounded text pages from a selected same-fund non-blind agent's tool-results/web-fetch folders. It accepts the genuine returned path or listed relative path, rejects state/scratchpads, traversal, symlink escapes and other funds. Missing or invented context paths stay explicit errors. It never exposes the whole private Dexter directory.

Prompts require current server mandate/policy inspection, independent research/challenge, registered immutable target weights plus a readable markdown strategy, blind evaluation, final adversarial review and human execution gates. Zero allocations are omitted; dates are already observed and bounded by actual snapshot availability. A live-selected strategy replay is disclosed as hindsight-contaminated, and Opus 4.6 does not make an unknown author clean. Arbitrary Python execution and real-money trading are unsupported. The final post-test review is enforced through review_strategy with the exact current evaluation_id; pre-test review alone cannot authorize execution or human approval. Continuous paper management means later authorized executor cycles under the same backend checks; schedules and timers do not grant permission.

Verification uses controllable worker processes and the actual pinned loop with fixture model responses. Tests cover background child handoffs, wakeups, slot limits, immediate stop during a one-hour timer/reacquisition, thread pagination/fund boundaries, result-file bounds/path escapes, supervision instead of false completion and a 27-turn pinned Dexter run with live tool history retained. No model, hosted, provider or broker requests are made by these tests. A coordinated deployment and real hosted verification remain separate steps.


The main list_agents graph includes every fund node, including nested descendants. Nodes expose bounded objective/recentResult/recentActivity, parentId/role/model, and lifecycle. `report_agent_progress` records workflow status/phase/blocker/artifacts as a self-report; blocked requires a concrete reason. Lifecycle is working/queued/waiting/monitoring while a task runs, then blocked/completed only from an explicit report, or idle/stopped/error. Backend gates and broker receipts remain the verification source. `read_agent_thread` is the bounded drill-down. The canvas owner consumes these optional snapshot fields.

Human delegated paper criteria selection to orchestrator/strategy. `configure_paper_policy` chooses and records low evaluation thresholds and order limits before testing, with version, author and rationale. Saved mandate universe, position/drawdown limits, permissions and approval settings are inherited; stop remains engaged and cash/sector constraints remain intact. Changed agent criteria are rejected after any observed test. Results/approvals include the exact policy version. Blind evaluators and other roles cannot configure policy. Current prompts give very low numerical examples without changing real observed metrics or guaranteeing PASS.

`alpaca_paper_market` reads fresh snapshots/clock through the existing Alpaca adapter, bypassing its snapshot cache and exposing IEX feed scope, exchange timestamps and ages. It has no stale historical fallback and submits nothing. IEX is a venue subset, not consolidated SIP. Paper account and definitive fill lookups remain separate tools.

Cash-reserve and sector enforcement landed in the coordinated cash patch. Strategy instructions and register_strategy now preserve an explicit cash remainder and direct reserve-aware allocations instead of a fully invested synthesis seed. The WF gate does not normalize that cash away, and planner/submission recheck projected cash and sector exposure. Sector labels use the existing ten-name static mapping, not a live classification feed. Historical cash reserve is a monthly target, not a guaranteed continuous floor. This change does not relax the mandate. No verification workflow or order was started by this work.
